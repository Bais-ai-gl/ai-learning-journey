## 博客 1：《手写 RAG：从 0 到 1 的检索增强问答》

**发布渠道**：掘金 / CSDN

**结构（5 段）**：

1. **问题**：大模型为什么会「幻觉」？（训练目标只是 next-token prediction，会编造）
2. **方案**：RAG = 先检索、再生成，让模型「照资料回答」。画一张流程图：文档 → 分块 → 向量化 → 建索引 → 检索 top-k → 拼 prompt → 生成
3. **实现**：不用框架手写 5 个环节，贴核心代码（chunk_text / embed / FAISS / retrieve / generate）
4. **效果**：用 3 篇示例文档跑通，展示「带引用来源」的回答截图
5. **反思**：踩过的坑（系统代理 502、huggingface 镜像、模型冷启动），以及「为什么检索不到 / 引用错误」的下一步优化方向（混合检索 + 重排）

**金句**：RAG 不是「把知识喂给模型」，而是「给模型一本可以翻的书」。

## 博客 2：《手写 ReAct：让大模型自己调工具》

**发布渠道**：掘金 / CSDN

**结构（5 段）**：

1. **问题**：大模型不会算数、不知道实时信息、查不了数据库 —— 因为它只会「说话」，不会「动手」
2. **方案**：Agent = 大模型 + 工具 + 循环决策。ReAct = 推理(Reasoning) + 行动(Acting) 交替
3. **实现**：手写 while 循环（Thought → Action → Observation → Answer），贴核心代码和 3 个工具（计算器/查天气/查库）
4. **效果**：展示「北京天气 + 算 3.5*7+2」连续调 2 个工具的完整过程截图
5. **反思**：为什么「把工具结果拼回对话继续」是精髓；手写版 vs LangGraph 框架版的区别（状态图/条件分支）

**金句**：Agent 不是更聪明的模型，而是「会使用工具」的模型。
