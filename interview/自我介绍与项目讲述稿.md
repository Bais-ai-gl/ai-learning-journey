## 二、项目 STAR 讲述稿

### 项目 1：企业知识库 RAG 问答系统

- **S（情境）**：企业内部文档（制度、产品、FAQ）分散在各处，员工找答案慢；直接用大模型又不知道内部知识、还爱编造。
- **T（任务）**：做一个基于企业私有文档、回答可溯源、不瞎编的问答系统。
- **A（行动）**：文档清洗 → 分块 → embedding（bge-small-zh）→ FAISS 向量库 → 检索 top-k → 拼进 prompt → 大模型生成，并强制带引用来源。
- **R（结果）**：常见问题命中率从 {XX%} 提升到 {XX%}，回答可溯源、幻觉明显下降（用具体数字）。

### 项目 2：数据分析 Agent

- **S（情境）**：业务方提「帮我看看最近销售趋势」这类自然语言需求，每次都要人工写 SQL/脚本，效率低。
- **T（任务）**：做一个能听懂自然语言、自己拆步骤、调工具取数分析的 Agent。
- **A（行动）**：用 Function Calling 定义取数/画图工具，让模型做 ReAct 式「思考-调用-观察」循环，出错自动重试。
- **R（结果）**：常见取数需求从 {X 分钟} 降到 {X 秒}，非技术人员也能自助查数。

### 项目 3：LoRA 微调

- **S（情境）**：开源模型回答不符合公司文风/领域术语，Prompt 调来调去也不稳定。
- **T（任务）**：用少量标注数据，把模型调成特定风格/领域的专用模型。
- **A（行动）**：构造指令数据集 → QLoRA 微调（4bit 量化 + LoRA）→ 调 rank/学习率 → 用验证集和人工评分评估 → 合并权重部署。
- **R（结果）**：风格符合度从 {X} 提到 {X}，单卡就能训、成本可控。

### 项目 4：端到端风控模型

- **S（情境）**：业务存在欺诈/坏账风险，靠规则漏判、误判多。
- **T（任务）**：从原始数据到上线，做一套可用的风控评分模型。
- **A（行动）**：特征工程（缺失/类别/分箱）→ 选模型（XGBoost，兼顾效果和可解释）→ 处理类别不平衡 → 调参 → 定阈值 → 部署上线并监控。
- **R（结果）**：在控制误拒率的前提下，坏样本识别率提升 {XX%}。

## 三、每个项目的 5 个「为什么」（面试官最爱追问）

### 项目 1：RAG 问答系统

1. **为什么用 RAG 而不是微调？** —— 企业知识更新快、要求可溯源，RAG 改知识不用重训模型，成本低、可控。
2. **为什么用 FAISS 而不是别的向量库？** —— 本地轻量、上手快、支持 GPU；数据量大可换 Milvus 等分布式方案。
3. **为什么选 bge-small-zh 这个 embedding 模型？** —— 中文效果好、体积小、快，性价比高。
4. **分块大小怎么定的？为什么？** —— 按语义/章节分，兼顾「检索准」和「上下文完整」，太小丢上下文、太大稀释相关性。
5. **检索回来的内容怎么防「答非所问」或幻觉？** —— 设相似度阈值、top-k 截断、强制引用来源、不命中就答「不知道」。

### 项目 2：数据分析 Agent

1. **为什么用 Agent 而不是写死流程？** —— 需求多变、步骤不固定，Agent 能自己规划，写死流程维护成本高。
2. **为什么用 Function Calling 而不是让模型直接生成 SQL？** —— 让模型只出参数、代码执行，结果可靠、可校验、可加权限控制。
3. **怎么保证生成的调用/查询安全正确？** —— 只开放白名单工具、校验参数、SQL 走只读权限、结果回填后再让模型检查。
4. **工具调用出错怎么兜底？** —— 把报错信息回填给模型，让它重试或换思路，设最大重试次数防死循环。
5. **为什么要加记忆/上下文？** —— 多轮追问要记得前面的查询条件，短对话放上下文、长期偏好放外部存储。

### 项目 3：LoRA 微调

1. **为什么用 LoRA 而不是全量微调？** —— 显存省、训练快、可插拔，一个底座出多个 LoRA；全量微调成本和门槛都高。
2. **LoRA 的 rank 选多少？怎么定的？** —— 从小 rank 试起（如 8/16），看验证集效果和成本权衡，rank 越大拟合越强也越容易过拟合。
3. **数据哪来的？怎么构造指令数据？** —— 从真实业务语料 + 人工改写，做成「指令-输入-输出」三元组，保证多样性和质量。
4. **怎么评估微调效果（指标）？** —— 验证集 loss + 人工评分（风格/准确/安全），必要时用 GPT 当裁判打分。
5. **微调后线上怎么部署？推理会变慢吗？** —— 把 LoRA 权重合并进底座再部署，推理速度不变；用 vLLM 等服务框架提吞吐。

### 项目 4：端到端风控模型

1. **为什么选 XGBoost 而不是深度学习？** —— 表格数据上 XGBoost 效果强、训练快、可解释（要能向业务/监管解释），性价比高。
2. **特征怎么来的？怎么处理缺失/类别变量？** —— 从交易/行为数据衍生特征；缺失单独标记或填充，类别用分箱/编码。
3. **风控里为什么不能只看准确率？** —— 坏样本少，准确率会骗人；看 AUC、召回率、KS，按业务定误拒/误放成本。
4. **数据不平衡怎么办？** —— 上采样/下采样、给样本加权、调阈值，并结合业务成本选择。
5. **线上怎么保证实时性和防模型漂移？** —— 特征线上化、低延迟打分服务，持续监控 PSI/指标，漂移就重训。
